# 《쓰이지 않은 마을》 — 제출 빌드

문장특별시의 야간 조사원이 되어 종이로 접힌 마을을 탐험하는 한국어 1인칭 포인트앤클릭 공포 게임입니다. 발견한 문장을 기록하거나 삭제할수록 주인공의 인물 설정이 굳고, 반복된 행동과 반대되는 선택은 경고·잉크 비용을 거쳐 실제로 붉은 줄에 삭제됩니다.

## 실행

```bash
npm install
npm run dev
```

## 검증

```bash
npm test
npx tsc --noEmit
npm run build
npm audit
```

## 플레이

- 화면의 좌우 화살표 또는 `A`/`D`, 키보드 방향키: 현재 개방된 장소 둘러보기
- 전경의 서로 다른 두 구역 프레임: 해당 장소의 1·2번 세부 장면으로 진입
- 세부 장면에 놓인 바닥·선반·책상 위 투명 소품: 아이템 수집 또는 물리적 단서 기록
- `전경으로 돌아가기` 또는 `Escape`: 세부 장면에서 현재 장소 전경으로 복귀
- 소지품 카드: 장면에 사용할 물건 선택
- 카드의 `조사`: 물건의 형태와 용도 확인
- 카드의 `조합`: 첫 물건을 지정한 후 다른 물건의 `합치기` 선택
- 세부 장면의 `사용`: 선택한 물건을 조사 중인 환경에 적용
- 단서 소품: `[문장을 기록한다]` 또는 `[붉은 줄로 삭제한다]`를 결정
- 수정액: 인물 설정 때문에 완전히 삭제된 선택 하나를 한 번 복원
- `기록`: 직접 발견한 선택 단서 열람
- `일시정지`, 자동 저장, 초기화, 키보드·마우스·터치 지원

## 진행 구성

### ACT 1 · 잠긴 기록관

종이 광장, 여백의 숲, 잉크 우물, 폐쇄된 인쇄소를 조사해 열쇠와 문장 등잔을 제작합니다. 중앙기록관 입구를 열기 전에는 내부와 후반 장소에 접근할 수 없습니다.

### ACT 2 · 삭제된 세 이름

서고에서 삭제 명단을 밝히면 버려진 교실, 종이 예배당, 검은 강둑이 개방됩니다. 각 장소에는 별도의 발견물 두 개, 조합식 하나, 이름 복원 상호작용 하나가 있습니다.

### ACT 3 · 마지막 원고

세 이름을 모두 복원해야 편집자의 방에 들어갈 수 있습니다. 누적된 인물상에 따라 복원·자기 삭제 중 하나가 지워질 수 있으며, 모순을 두 번 감수하고 다시 미정 상태로 돌아오면 세 번째 결말이 나타납니다.

## 콘텐츠

- 열 개의 고유 장소 전경과 기본·보조로 나뉜 별도의 1280×720 세부 조사 배경 20종
- 바닥·선반·책상에 직접 놓이는 투명 아이템·단서 소품 WebP
- 환경 조사 지점 22개
- 선택 기록 12개와 저널
- 아이템 16종과 조합식 5개
- 이름 조각 3개
- 진행에 따라 나타나는 붉은 편집자 그림자와 긴장도
- 복원·자기 삭제·숨겨진 사람 엔딩
- 버전 6 `localStorage` 자동 저장과 버전 5 무손실 중립 마이그레이션
- `prefers-reduced-motion` 대응
- 외부 런타임 이미지·폰트·API 의존성 없음

## 프로젝트 구조

- `src/engine.ts`: 장소 잠금, 조사, 조합, 편집 성향, 선택 삭제, 수정액과 세 엔딩을 다루는 순수 상태 엔진
- `src/main.ts`: 한국어 탐험 UI, 저널, 튜토리얼, 인벤토리, 키보드·터치 입력
- `src/style.css`: 전경 진입 프레임·세부 소품·편집자 그림자·반응형·엔딩 연출
- `src/engine.test.ts`: 기록자·삭제자·사람의 세 전체 경로와 교정 임계값을 검증
- `public/art/scenes/`: 한자나 텍스트가 없는 열 개의 정적 WebP 배경
- `public/art/details/`: 전경의 특정 구역을 확대한 열 개의 세부 장면 WebP
- `public/art/items/`: 인게임 수집과 인벤토리에 함께 쓰는 아이템·문서 소품 WebP
- `.github/workflows/deploy-pages.yml`: `main` 푸시 또는 수동 실행 시 테스트 후 GitHub Pages 배포
- `DEVELOPMENT_LOG.md`: 대회 제출용 설계 변화, 폐기 이유, 에이전트 협업, 검증 기록

현재 기능 브랜치를 푸시해도 Pages는 자동 공개되지 않습니다. 저장소의 Pages 소스를 GitHub Actions로 설정한 뒤 workflow를 수동 실행하거나, 검토된 제출판을 향후 `main`에 통합하면 정적 사이트가 배포됩니다.

정답 조합법과 마지막 반전은 README에 공개하지 않습니다. 저장 버전이 호환되지 않거나 손상되면 안전하게 새 게임으로 초기화됩니다.
